## `ask_user`

Ask the human operator a clarifying question when the request is ambiguous. Use this instead of guessing a pid, domain, service, or intent. The answer comes back as the tool result.

- **Risk:** read
- **Needs approval:** no
- **Roles:** viewer, operator, admin
- **Virtual:** handled by the CLI, never executed on the server
- **Arguments:**
  - `question` (string, required) a short, specific question for the operator.
- **Plan:**

  ```
  ask the operator: 'Which service do you mean?'
  ```

## `db_active_queries`

List non-idle PostgreSQL backends: pid, user, state, wait event, age, and query text. Returns query text only, never result rows. Use the pid with db_cancel_query.

- **Risk:** read
- **Needs approval:** no
- **Roles:** viewer, operator, admin
- **Arguments:**
  - `limit` (integer, default `10`) max backends to show (1-20).
- **Plan:**

  ```
  SELECT pid,
         usename,
         state,
         wait_event_type,
         date_trunc('second', now() - query_start) AS age,
         left(regexp_replace(query, '\s+', ' ', 'g'), 300) AS query
  FROM pg_stat_activity
  WHERE backend_type = 'client backend'
    AND pid <> pg_backend_pid()
    AND state <> 'idle'
  ORDER BY query_start NULLS LAST
  LIMIT 10
  ```

## `db_locks`

Show PostgreSQL lock chains: which backends are blocked and by whom (pg_blocking_pids).

- **Risk:** read
- **Needs approval:** no
- **Roles:** viewer, operator, admin
- **Plan:**

  ```
  SELECT a.pid,
         a.usename,
         a.state,
         a.wait_event_type,
         pg_blocking_pids(a.pid) AS blocked_by,
         date_trunc('second', now() - a.query_start) AS age,
         left(regexp_replace(a.query, '\s+', ' ', 'g'), 300) AS query
  FROM pg_stat_activity a
  WHERE cardinality(pg_blocking_pids(a.pid)) > 0
     OR a.pid IN (SELECT unnest(pg_blocking_pids(b.pid)) FROM pg_stat_activity b)
  ORDER BY a.query_start NULLS LAST
  LIMIT 50
  ```

## `io_top`

List processes doing the most disk I/O over a 1-second window.

- **Risk:** read
- **Needs approval:** no
- **Roles:** viewer, operator, admin
- **Arguments:**
  - `limit` (integer, default `10`) how many processes to show (1-25).
- **Plan:**

  ```
  psutil per-process io_counters() delta sampled over 1s
  ```

## `load_avg`

Show 1/5/15-minute load average, CPU count, and memory/swap headroom. Start here for any "server is slow" question. Load above the CPU count means processes are queuing for CPU (or stuck in uninterruptible I/O wait).

- **Risk:** read
- **Needs approval:** no
- **Roles:** viewer, operator, admin
- **Plan:**

  ```
  cat /proc/loadavg; nproc; free -m
  ```

## `service_logs`

Fetch the most recent journal lines for a systemd service.

- **Risk:** read
- **Needs approval:** no
- **Roles:** viewer, operator, admin
- **Arguments:**
  - `service` (enum: nginx, gunicorn, celery, postgresql, required) one of nginx, gunicorn, celery, postgresql.
  - `lines` (integer, default `100`) how many lines to fetch (1-500).
- **Plan:**

  ```
  journalctl -u nginx -n 100 --no-pager -o short-iso
  ```

## `top_processes`

- **Risk:** read
- **Needs approval:** no
- **Roles:** viewer, operator, admin
- **Arguments:**
  - `limit` (integer, default `10`) how many processes to show (1-25).
- **Plan:**

  ```

  ```
